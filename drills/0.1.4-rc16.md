reviewer's qemu OOM-killed on a 12 GiB host (crew#845) and the incus 6.0 stop
(heavy-duty/box#307). A re-run on a 24 GiB host read both green

on that host read every leg green. `0.1.4-rc15`'s round read 17 green and two
red, one cause: the breaker leg graded a tick before its run ended
([`drills/0.1.4-rc15.md`](0.1.4-rc15.md), crew#850). Since the rc8 tag:

- **#792 (engine and CLI): box 0.11.0.** One door into a box
  (`shared/lib/box-entry.sh`: `box exec --user <agent>` on box 0.11.0 or
  later, the old entry on an older box, read from `box --version`). The mint
  drops `box new --user` and makes the tenant with `rig bootstrap <agent>-box
  --user <agent>`. The rig floor is `0.4.1`.
- **#822 (CLI, installer, floor, drill): crew as one service per machine.**
  `sudo crew service setup` makes the `crew` account and group, the
  `box grant --service crew --share crew` with caps, a sudoers rule for the
  group, `/etc/crew/service.conf`, the floor unit, and the tick, restart and
  reset timers. Fleets and state live under `/var/lib/crew`. Every other verb
  re-runs as the account, and per-user mode is gone. The drill gains the
  declared leg `service`.
- **#818 (drill):** the closing teardown line names `--box crew-drill-floor`.
- **#825 (drill): the round provisions its own host.** `drill/provision.sh`
  installs box at the drill's pin (`DRILL_BOX_REF`, 0.11.0) with
  `box setup-host` when it is absent, plus the host tools and the browser
  leg's node, npm, Chromium and playwright-core. It never replaces an
  installed box, refuses inside a box, and the summary names the box.
- **#828 (drill): the round keeps its own credential pool.**
  `~/.config/crew-drill/credentials` (`drill/creds.sh`), used unless
  `CREW_CREDENTIALS_DIR` is set. Missing `--creds` entries, and the Telegram
  chat, are asked for on the terminal. Without a terminal, the round refuses
  and prints `drill/creds.sh …`. The floor's workspaces test also waits for a
  child floor's first snapshot (a CI race).
- **#831 (CLI, floor, drill): a crew server starts with no fleets.**
  `crew service setup` makes none. The floor with an empty index serves a
  lobby (`fleet-floor/server/floor/lobby.html`) whose one action is New fleet,
  then opens the fleet made, and fleet-scoped APIs answer 404. The CLI says
  `no fleet on this host yet`, and the scheduled walks exit 4 (nothing to do).
  The `service` leg reads the empty start and makes its fleet through New
  fleet.
- **#832 (engine): the rc11 round's finding.** The door into a box retries a
  box that is not answering (`BOX_ENTRY_ANSWER_S`, 90 s) and names it so, with
  box's own error, instead of reading it as a box with no user.
- **#840 (drill, CLI, engine): the rc12 round's findings.**
  - #835: `--creds` takes two `gh:` entries, used by case. The first logs the
    boxes in; the other makes the round's own calls (sandbox owner, issue and
    PR author, teardown). One account on both sides is refused at startup.
    This replaces #828's stand-in.
  - #836: the builder's PR discovery and the review sweep read only a real
    pulls answer, never an error body.
  - #837: the round installs box as root, system-wide. `crew service setup`
    refuses a box off its units' PATH, and the service leg prints a failed
    setup's output.
  - #838: the armed app pass serves its own fleet definition
    (`--drill-roles`).
  - #839: `box_down_settled` (wait for the boot, stop, retry once) is used by
    restart, down and reset.
- **#843 (drill): the rc13 round's finding.** Before the roles mint in
  parallel, the round warms incus's per-remote image cache (one
  `incus image list <remote>:` per simplestreams remote), so first launches on
  a cold drill host no longer race on incus's cache directory (#842).
- **#846 (drill): the rc14 round's finding.** `--parallel` sums the role
  boxes' memory (triage 4 GiB, builder and reviewer 8 GiB) plus 2 GiB of
  headroom against the host's, and runs the roles in waves that fit when they
  do not, saying the plan. floor-provision and service read INCOMPLETE, with
  the numbers, on a host with too little free to mint their box. The summary
  names any qemu the host's kernel OOM-killed (`## HOST OUT OF MEMORY`) (#845).
- **#851 (drill, host floor): the rc15 round's findings.**
  - #850: the breaker leg grades a tick only once its run has written
    `duty run end`, re-reading a slice whose `box exec` returned early, and
    says so (`the tick returned before its run ended …`).
  - #849: the armed box is restored once; a green round ends with no stray
    "NOT fully restored" line.
  - #847: a floor job reads finished only after it released the one-job slot
    and the maintenance lock, so the next job is not refused with a 409.

The engine inside the boxes changes in how a box is entered and minted, and in
how two tick paths read a failed pulls call (#836).
The service model, the empty start, the provisioning and the pool are host-side. All of it is read on a
real host here. On box 0.11.0, the rc14 tag's full round read every leg
green, and rc15 read every leg green but `breaker`, whose engine reading was
right and whose grading was not (#850).

## The round this file is waiting for

On heavy-duty/infra's drill-host VM (or any non-box machine where the operator
has passwordless sudo), from a local checkout **at the published tag**:

    git clone --branch 0.1.4-rc16 git@github.com:heavy-duty/crew.git ~/Projects/crew-rc16
    git -C ~/Projects/infra pull                  # infra#136: drillhost sizes
    runbooks/drill-host/drillhost.sh resize --size l   # once: 8 cpu / 24 GiB, kept across resets
    runbooks/drill-host/drillhost.sh reset        # or `up --size l`, the first time
    runbooks/drill-host/drillhost.sh run crew --from ~/Projects/crew-rc16 -- \
      --parallel --creds gh:<box account>,gh:<round account>,agent:<name>,tg:<name>

- **The tree is the tag.** drillhost pushes the checkout into the VM and runs
  the round with `--tree`, so nothing is fetched inside it. The summary's
  `## drilled source:` line must name the tag's commit.
- **The round provisions the VM** (#825): box `0.11.0`, installed system-wide
  as root (#837), with `box setup-host`, the host tools and the browser leg's
  dependencies. Its first lines are `provision: …`, and the summary's
  `## drill host: box 0.11.0` line is part of the reading.
- **The round asks for the credentials** (#828) on the operator's terminal,
  which drillhost passes through (heavy-duty/infra#131): both `gh:` secrets,
  the `agent:` and `tg:` secrets, and the Telegram chat id, once per clean VM.
  The two `gh:` entries are two accounts (#835). The first logs the boxes in;
  the other makes the round's own calls, owns the sandboxes, and needs
  `delete_repo`. Its startup line `== gh: the boxes log in as … ; the round's
  own calls are …` names both accounts, and they must differ.
- **The memory plan (#845).** Before the roles start, the round prints
  `== --parallel: triage 4GiB + builder 8GiB + reviewer 8GiB + 2GiB headroom
  fits this host's 24GiB (#845)` on a size `l` VM. On a smaller one it runs
  waves and says so; that is still a full round, only slower. The summary has
  no `## HOST OUT OF MEMORY` line, and floor-provision and service run.
- **The breaker leg (#850).** If a tick comes back early, the triage section
  says `the tick returned before its run ended (tick.sh rc N); re-read its
  slice K time(s) …` and still grades the run whole. Copy those lines into the
  record: they are #850's open half.
- **The incus stop.** A fresh mint that dies with an empty console after its
  second start is heavy-duty/box#307 (lxc/incus#4407, incus 6.0), not crew's.
  Until box 0.11.1, a round that hits it is re-run whole for G2.
- **Every leg green, browser included, in one round:** preflight must print no
  `the browser leg will read INCOMPLETE` line.
- **`service`** runs on the VM's passwordless sudo, under scratch names only,
  and is torn down with `--purge`.
- **No `--keep`.** The VM is thrown away, and without it the `teardown` leg is
  read too: 17 of 17.
- **`--fast` is never cited.** Its summary opens `## TIER: fast`

**The restart rule (#753, 2026-11-24).** A defect found during the week is
fixed on `main` as the next candidate, which replaces the running one on both
fleets. The seven days continue for a fix that leaves alone what runs inside
the boxes (docs, tests, the drill, host-side CLI or floor, the installer). They
restart for an engine change: `shared/bin/`, `shared/lib/` outside
`shared/lib/host/`, `shared/conf/` or `shared/prompts/`. The record names
which case each fix was, and a fix touching both restarts the clock.

If the round or the run finds a defect, the fix lands on `main`
(`0.1.4-rc17-dev`) and the next candidate is `0.1.4-rc17`. If it holds,
`0.1.4` is promoted stable from this candidate, by stamps only. A final may
differ from its last candidate by stamps only.
