## What crew#903 changes on a host

- **#898 — a member's intent, which the host tick obeys.** One file per member
  (`<config>/store/intent/<box>`), written by the CLI and read by the tick, the
  CLI and the floor alike. The tick never starts a member that is not on duty.
  - `crew stop [--force]` / the floor's **Stop**: held off, keeping its
    claims; it finishes its run (`stopping`), then the tick drains and stops
    it; **Force stop** (a checkbox) ends the session now with `incus stop
    --force`, exec'ing nothing into the box first. A graceful stop never
    escalates on its own (#486 D1). Only `crew start` / **Start** lifts it.
  - `crew pause` / **Pause**: the running box is frozen in place (`box incus
    <box> -- pause`); `crew resume` / **Resume** continues the same session,
    however long from now. A frozen box counts against the running cap; a
    freeze does not survive a host restart, and the member then reads stopped.
  - `crew unhire [--logout]` / **Unhire**: its claims go back to the board
    (an issue whose work is already its pull request is kept and named), its
    cron is disarmed, its box drained, stopped and kept. `crew hire` puts it
    back.
  - `crew logout <box> gh|agent|tg` / a pool service set to *none*: the login
    is deleted from the box and its entry unassigned; the tick does not wake a
    member with no gh or agent login.
  - A member paused before #898 (the old `store/paused/<box>` marker) reads as
    stopped; `crew resume` on it is Start. `crew up`, `hire-all`, `restart
    --all`, `reset --all` and wake-silent leave a held member alone. The tick
    also records, from the rows it already reads, a member's items waiting on
    a person (`state:needs-human`) and the repositories its box was staged
    without.
- **#900 — one action control on the floor:** every action button disables at
  once, says "Pausing… 12s · step" while it runs, blocks its member's other
  controls with a tooltip naming what holds them, and says its verdict beside
  itself; confirmations (Stop's force checkbox, Unhire's logout checkbox) are
  one dialog.
- **#899 — health stats:** a member's page shows its last 24 hours by status,
  from the store's one row per change (`status_log`, `/api/health`).
- **#902 — the floor's tests in four independent parts** (`collector`, `cli`,
  `page`, `page-live`), a path map, one CI job per part under one `ci-floor`
  check; ci-floor's pull-request trigger names `cli/crew` and
  `shared/lib/host/**`.

**The restart rule (#753, 2026-11-24).** A defect found during the week is
fixed on `main` as the next candidate, which replaces the running one on both
fleets. The seven days continue for a fix that leaves alone what runs inside
the boxes (docs, tests, the drill, host-side CLI or floor, the installer). They
restart for an engine change: `shared/bin/`, `shared/lib/` outside
`shared/lib/host/`, `shared/conf/` or `shared/prompts/`. The record names
which case each fix was, and a fix touching both restarts the clock.

(`0.1.4-rc25-dev`) and the next candidate is `0.1.4-rc25`. If it holds, `0.1.4` is promoted stable from this candidate,
by stamps only. A final may differ from its last candidate by stamps only.
