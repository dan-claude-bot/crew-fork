### The two failures, traced

- **triage → #809 (engine) and #810 (harness).** The drill's tick for the
  stray, at 08:22:12, was refused 2 s after the previous run had ended:
  `tick skipped: previous run still holds the lock`. The duty lock is taken
  in flock's command form, so every child inherits its descriptor. The
  memory watchers (`_session_peak_rss_watch`, `_session_mem_watch`) were
  stopped with a TERM that killed the bash subshell, but not the foreground
  `sleep` it was waiting on. That orphaned `sleep` held the lock for up to a
  poll interval after the run ended (#809). The drill ticked once and took
  the refusal as a tick (#810). The stray was ruled only at 08:43,
  after the leg's 900 s window had closed.
- **release → #811 (engine).** The release session opened PR #6
  (`release/drill20261123084453-0.0.2`, labelled `release`) at 08:45:35. At
  08:45:43 the engine's confirmation, `gh pr list --label release`, read it
  absent: `--label` goes through GitHub's search index, which had not yet
  indexed a PR eight seconds old. The engine warned "the session ended
  without opening release/…-0.0.2 (try 1 of 2)" and the leg failed. The
  session did open the PR, and the session log shows it.

Both races predate rc6: the code paths are the same back to at least rc4.
rc6 is the first round that lost them.
