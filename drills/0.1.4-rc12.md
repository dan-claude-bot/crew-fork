## Why a round is needed

The last tree drilled green on a real host is the `0.1.4-rc8` tag (`e3675e4`),
recorded in [`drills/0.1.4-rc8.md`](0.1.4-rc8.md): every declared leg green in
one round, on box 0.10.0. `0.1.4-rc9` and `0.1.4-rc10` were published but never
drilled. `0.1.4-rc11`'s round read red at its first step
([`drills/0.1.4-rc11.md`](0.1.4-rc11.md), crew#832). Since the rc8 tag:

- **#792 (engine and CLI): box 0.11.0.** One door into a box
  (`shared/lib/box-entry.sh`: `box exec --user <agent>` on box 0.11.0 or
  later, the old entry on an older box, read from `box --version`). The mint
  drops `box new --user` and makes the tenant with `rig bootstrap <agent>-box
  --user <agent>`. The rig floor is `0.4.1`.
- **#822 (CLI, installer, floor, drill): crew as one service per machine.**
  `sudo crew service setup` makes the `crew` account and group, the
  `box grant --service crew --share crew` with caps, a sudoers rule for the
  group, `/etc/crew/service.conf`, the floor unit, and the tick, restart and
  reset timers. Fleets and state live under `/var/lib/crew`. Every other verb
  re-runs as the account, and per-user mode is gone. The drill gains the
  declared leg `service`.
- **#818 (drill):** the closing teardown line names `--box crew-drill-floor`.
- **#825 (drill): the round provisions its own host.** `drill/provision.sh`
  installs box at the drill's pin (`DRILL_BOX_REF`, 0.11.0) with
  `box setup-host` when it is absent, plus the host tools and the browser
  leg's node, npm, Chromium and playwright-core. It never replaces an
  installed box, refuses inside a box, and the summary names the box.
- **#828 (drill): the round keeps its own credential pool.**
  `~/.config/crew-drill/credentials` (`drill/creds.sh`), used unless
  `CREW_CREDENTIALS_DIR` is set. Missing `--creds` entries, and the Telegram
  chat, are asked for on the terminal. Without a terminal, the round refuses
  and prints `drill/creds.sh …`. A logged-out host `gh` uses the `gh:` entry's
  token. The floor's workspaces test also waits for a child floor's first
  snapshot (a CI race).
- **#831 (CLI, floor, drill): a crew server starts with no fleets.**
  `crew service setup` makes none. The floor with an empty index serves a
  lobby (`fleet-floor/server/floor/lobby.html`) whose one action is New fleet,
  then opens the fleet made, and fleet-scoped APIs answer 404. The CLI says
  `no fleet on this host yet`, and the scheduled walks exit 4 (nothing to do).
  The `service` leg reads the empty start and makes its fleet through New
  fleet.
- **#832 (engine): the rc11 round's finding.** The door into a box retries a
  box that is not answering (`BOX_ENTRY_ANSWER_S`, 90 s) and names it so, with
  box's own error, instead of reading it as a box with no user.

The engine inside the boxes changes only in how a box is entered and minted.
The service model, the empty start, the provisioning and the pool are host-side. All of it is read on a
real host for the first time here, and this is the first round on box 0.11.0.

  `service setup` refuses a box off its units' PATH, and a failed setup's
  output is printed.
