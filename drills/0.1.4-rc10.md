## Why a round is needed

The last tree drilled on a real host is the `0.1.4-rc8` tag (`e3675e4`),
recorded in [`drills/0.1.4-rc8.md`](0.1.4-rc8.md): every declared leg green in
one round, on box 0.10.0. `0.1.4-rc9` was published but never drilled
([`drills/0.1.4-rc9.md`](0.1.4-rc9.md)). Since the rc8 tag:

- **#792 (engine and CLI): box 0.11.0.** One door into a box
  (`shared/lib/box-entry.sh`: `box exec --user <agent>` on box 0.11.0 or
  later, the old entry on an older box, read from `box --version`). The mint
  drops `box new --user` and makes the tenant with `rig bootstrap <agent>-box
  --user <agent>`. The rig floor is `0.4.1`.
- **#822 (CLI, installer, floor, drill): crew as one service per machine.**
  `sudo crew service setup` makes the `crew` account and group, the
  `box grant --service crew --share crew` with caps, a sudoers rule for the
  group, `/etc/crew/service.conf`, the floor unit, and the tick, restart and
  reset timers. Fleets and state live under `/var/lib/crew`. Every other verb
  re-runs as the account, and per-user mode is gone. The drill gains the
  declared leg `service`.
- **#818 (drill):** the closing teardown line names `--box crew-drill-floor`.
- **#825 (drill): the round provisions its own host.** `drill/provision.sh`
  installs box at the drill's pin (`DRILL_BOX_REF`, 0.11.0) with
  `box setup-host` when it is absent, plus the host tools and the browser
  leg's node, npm, Chromium and playwright-core. It never replaces an
  installed box, refuses inside a box, and the summary names the box.

The engine inside the boxes changes only in how a box is entered and minted.
The service model and the provisioning are host-side. All of it is read on a
real host for the first time here, and this is the first round on box 0.11.0.

## The round this file is waiting for

On heavy-duty/infra's drill-host VM (or any non-box machine where the operator
has passwordless sudo), from a local checkout **at the published tag**:

    git -C ~/work/crew fetch --tags && git -C ~/work/crew checkout 0.1.4-rc10
    runbooks/drill-host/drillhost.sh up
    runbooks/drill-host/drillhost.sh run crew --from ~/work/crew -- \
      --parallel --creds gh:<name>,agent:<name>,tg:<name>

- **The tree is the tag.** drillhost pushes the checkout into the VM and runs
  the round with `--tree`, so nothing is fetched inside it. The summary's
  `## drilled source:` line must name the tag's commit. A bare `main` checkout
  would drill `0.1.4-rc11-dev`, which is not this candidate.
- **The round provisions the VM** (#825): box `0.11.0` with `box setup-host`,
  the host tools and the browser leg's dependencies. Its first lines are
  `provision: …`, and the summary's `## drill host: box 0.11.0` line is part of
  the reading. The operator still sets up the credentials behind `--creds`,
  and `gh`'s login, for `op` in the VM.
- **Every leg green, browser included, in one round:** preflight must print no
  `the browser leg will read INCOMPLETE` line.
- **`service`** runs on the VM's passwordless sudo, under scratch names only,
  and is torn down with `--purge`.
- **No `--keep`.** The VM is thrown away, and without it the `teardown` leg is
  read too: 17 of 17.
- **`--fast` is never cited.** Its summary opens `## TIER: fast`
  (`drills/README.md`).
